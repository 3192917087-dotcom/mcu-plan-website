# 按模型匹配生成策略

本地版本：20261018-2。使用者已切回DeepSeek，真实目录测试使用浏览器保存的DeepSeek配置。API设置仍由使用者填写并保存在当前浏览器，不包含内置密钥；不会把Kimi密钥复制给DeepSeek。原有K3兼容代码保留，但仅在明确选择K3模型时启用，其辅助资料理解不会在DeepSeek流程中执行。本文后面的K3数据为此前试用记录。使用者可阅读[论文生成路线](PAPER_GENERATION_ROUTE.md)审核当前流程和各类资料分支。

## 目录规划与参考目录

研究引入、总体方案、硬件、软件、测试、总结是内容职责，不再与固定章号绑定。目录支持3至12个连续章节，允许额外需求章节、软硬件合章或同一职责分章。图表和公式按实际职责及小节主题定位，写作、修复、字数分配与检查使用同一目录。

- 无参考：直接用本地默认六章结构，每章最后追加本章小结，三级标题仍按项目器件及功能安排；不花费一次目录API调用。
- 不完整参考：恢复可辨识章数、章名、局部分组和小结要求，其余合理补齐。明确总章数或最后结论章节可确定章数；截断在测试章不能据此认定总章数。已提供的小结须保留，“各章有小结”须逐章落实。
- 第一章已有两个及以上可辨识二级分组且接着第二章时，保留分组数及已给出的三级层级，不以默认四节覆盖；占位标题可按本课题命名。未单列主要内容或论文安排时，在既有框架内分段交代。只有第一章框架确实未给清楚时，才补齐必要标题。
- 清楚参考：保持明确章数、章名、内容分工及层级，将项目方案填入对应位置；不机械增加原目录未设的小结，不用默认六章覆盖它。
- 解析无空格编号、全角点、常见OCR漏点、星号占位及模糊文字要求；对每项参考内容记录最终对应小节与采用、调整或不适用理由。基础结构不能被直接忽略，采纳记录不能指向不存在的标题。
- 参考处粘入整篇模板时，提取编号框架与明确结构要求，过滤封面、正文、格式说明和授权声明；删除目录页码，识别被正文粘连的章标题，后出现的具体章节框架替换前面的占位目录。编号章节后的独立未编号结论须单独保留，不能挤入测试章小结。
- 选型已有位置就沿用；未提选型时在第二章合适处简要插入。普通篇幅选三四个重要器件，超过两万字适度增加；未提选型的参考保持简要。重复继电器型号共用一次选型，实际控制通道的电路和引脚说明分别保留。仅选定的重要器件安排器件图片与比较表，不强制所有器件比较；不把电阻、晶振等辅助件当关键选型项目。
- “微控制器的选择”也按选型识别。参考只有主控选型标题时，为其他关键器件拓展合理分组，不能将所有外设的选型图表塞到仅介绍主控的标题下面。
- 规划阶段核对连续编号、父子层级、重复标题及基础内容；不再硬性要求第一章恰好四个二级标题，也不限制所有课题采用同样的三级标题数。
- 缓存包含规则版本、实际资料、参考目录、目标字数和所选模型。重新生成已完成论文时重新规划；相同输入的断点续写复用有效规划。
- 最多一次生成和一次结构修复。仍不满足要求时在正文写作前停止并说明原因，保留原目录与原稿，不悄悄回退默认模板。
- 在检查之前整理可确定的模型返回差异：删除模型自行细拆的四级标题并将相应采纳记录指向保留的三级父节；仅引用整章的记录落到该章实际小节；没有实际APP/上位机需求且采纳理由已明确说明不适用的条目，按不适用记录。PCB默认启用，只有明确事实不使用PCB时才能省略。真正不存在的小节编号仍报错，不随意替换为别处。
- 参考资料支持图片、DOCX（含内嵌截图）、PDF、TXT/MD，读取文字/本地OCR后由AI解读原框架，原文字和解读结果均可查看。每份20 MB、最多12份/OCR页、合并5万字；超限报错，不截断。旧版DOC提示另存DOCX。AI解读按原文和读取规则版本缓存，失败保留原文字，不静默改回默认目录。
- 标题下的“可给出模块选型说明”等写作方向也绑定原位置，传入目录、正文及修复。小结的回顾性文字不能变为小结标题必须包含的全部关键词，避免误判触发反复修复。第一章可读标题同时核对原位置和三级标题，不能只留标题数量。
- PCB默认工具为嘉立创专业版，主控开发板可保留并配承载/接口PCB；用户明确不使用PCB或指定其他软件时遵守实际资料。不把电路板调试当作PCB设计，也不编造板层、尺寸和生产测量结果。
- 第一章论文组织说明从实际目录同步全部章号及章名，支持3至12章。初写、修复后及最终呈现均核对，替换旧章节清单时保留背景、研究内容和原标题层级。
- 图表按照实际目录定位，按实际小节顺序编号，不再固定依附2.4、4.1或5.4。正文必须遵循已规划标题，不能写作时重新套用默认结构。
- 生成页可展开查看实际目录和参考采纳说明，旧稿标记为已有稿件目录，不把历史稿件自动改写。
- 进度、请求状态与修复提示显示实际章名。完成进度为100%，结束后计时停止；补写正文插在本章小结之前。目录身份变化时将旧稿保存在项目的outlineHistory快照中，已被删除或职责变化的旧章节不混入新目录的字数、复核或导出；项目JSON备份包含这些快照。

## 写作前检查与中断修复

生成前先在本地核对题目、确认功能、主控、引脚、未确认冲突、已选择程序文件是否读取成功，以及默认项目目录的全部图表覆盖；通过后才调用文献、资料理解和目录API。缺失必需信息直接返回对应资料步骤，不先花费数分钟规划再失败。未上传程序、原理图和测试记录本身不阻止写作，写作依据和未验证部分分别记录。

2026-10-17原项目中断的原因是内部器件识别不一致：规划器把括号内容全部删掉后去重，检查器却按完整名称检查。因此“有源蜂鸣器”和“有源蜂鸣器（SD1209T5-A1）”分别要求计划却只生成一份；“红外避障传感器（左）”和“（右）”也被错误去重。现在规划与检查共用同一套器件身份：无歧义的通用名与具体型号共享图表及全部原始ID，左右、通道和控制对象区别保留，引脚不会混用；同名功能的原始ID也完整保留。不会改动用户确认的硬件事实。

K3辅助资料理解请求耗尽重试或仍有功能遗漏时，直接由完整的确认事实建立写作依据，继续生成，不为补一份辅助摘要中止整篇论文。用户主动暂停、账户或权限错误仍明确保留，不伪装为成功。网络重试有上限，持续网络故障仍可能暂停；现有章节和草稿可保存、下载和续作，不能承诺外部服务永不失败。

新增`node studio-v2/tests/paper-preflight-test.mjs`复现原项目的器件名称、左右引脚和功能覆盖问题，并验证缺资料时不会调用AI、可选资料不阻塞、辅助理解失败回退，以及主动暂停不会被吞掉。六个回归场景已通过；原项目浏览器预检也确认无遗漏图表、无引脚问题，已恢复至正文输出。

## Kimi K3

论文流程：确认资料和引脚 → 一次性统一理解项目 → 规划目录 → 逐章流式写作并保存草稿 → 校验图表与章节结构、精确局部修复 → 摘要 → 技术复核及必要修复 → 终稿检查及下载。

- 资料理解、引脚分析、目录、技术复核使用`reasoning_effort: high`；正文、局部修复、小任务使用`low`。不使用K3不支持的关闭思考参数，不默认使用`max`。
- 使用`max_completion_tokens`，在预计正文之外预留思考额度。励志语、连接检测不再用几十或几百token限制整个响应。
- 器件、方案、目录、文献推荐、摘要、检查结果等使用各自的严格JSON Schema，并做本地字段类型校验。思考过程永远不能被当成正文或JSON结果。
- 使用SSE流式接收，区分正在分析与正在输出，只展示进度、不展示思考内容。正文输出期间定期保存未完成草稿，正文全部返回后先保存再进行补强；暂停时可以下载已经返回的内容。已完整返回但未修复的草稿，继续时先修复而不重复付费写作。
- `finish_reason=length`视为未完成：文本有限次续写并保留完整assistant消息，JSON增加额度后重新生成完整对象。没有完成标记或连接中断不会当作成功。
- 修复优先返回原文片段和替换片段，只应用准确、唯一且互不重叠的补丁，再用原有内容规则复检。修复无效时保留原文和未解决问题，不声称全部通过。
- 技术复核聚焦硬件接口、功能逻辑、语义重复、数据矛盾及摘要细节；编号、格式及图表引用由本地规则检查。图表清单同步后再次核对修复是否实际保留，避免已经被覆盖的修改显示为已解决。
- 资料理解按项目事实、程序、测试资料及模型版本缓存；不替代或覆盖已确认的器件、功能和引脚。相同终稿和相同复核模型的已完成检查可以复用，内容变化后重新检查。
- 限流尊重`Retry-After`并退避；超时后降低推理强度。重试有次数上限，保持用户选择的K3模型，不静默换成其他服务。

统一理解是写作辅助资料，不能把缺失程序推断成已验证程序，不能新增方案未要求的功能。用户只提供题目或部分资料时，仍使用原有器件分析和确认流程补齐项目建议，并明确区分缺失依据。

## DeepSeek及共同修正

DeepSeek保留按任务启闭思考、JSON模式、分章写作和非流式接口。新传输层同时识别其输出截断，避免保存不完整章节为成稿。

共同修正：修复一个章节后继续处理其他章节；拒绝第一章修复时同时回退参考文献映射；章节原稿先于补强保存；段落拆分纳入修复效果评分；测试资料变化时使测试章节失效。正文、标题、题注样式以及DOCX导出逻辑没有更改。
